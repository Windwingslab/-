## 1. 调研得出、会改变方案的事实

| # | 事实 | 状态 | 对方案的影响 |
|---|---|---|---|
| F1 | 所有 CEP 扩展的后台脚本，和用户自己运行的脚本，**共用同一个 ExtendScript 全局环境**。同名全局变量由后加载的覆盖先加载的；AE 不支持 `#targetengine` | 【已核实】CEP 12 Cookbook「Load multiple JSX files」、AE Scripting Guide overview | 拆分后两个包不能都叫 `MH`。另外，用户脚本里写一句 `var MH = …`，今天就能让 5 个面板全部失灵，而 bridge.js 只看 `typeof MH`，发现不了 |

## 3. 需求 B：Studio（含实况照片）独立成扩展，版本 3.8.0（约 9 人日）

### 3.1 拆成什么样

两个方案独立设计，再由评审取舍：
- 「最小改动」：现有文件夹就是安装包，旁边再放一个；
- 「共享包 + 构建」：monorepo 加构建脚本。

**结论：采用「最小改动」作为主体，嫁接后者的 9 个好点子。** 对一人团队来说，风险、维护成本和工作量是硬约束：前者约 9 人日，后者约 20 人日；后者的源码不再等于安装包，报错行号还要换算。

| | 面板包（原地不动） | Studio 包（新） |
|---|---|---|
| 文件夹 = 包 ID | `com.windwings.motionhub` | `com.windwings.studio` |
| 扩展 ID | `…panel1`–`panel4`（不变） | **沿用** `com.windwings.motionhub.studio` |
| 菜单 | MotionHub / 2 / 3 / 4（不变） | MotionHub Studio · 剪辑排版（不变） |
| 后台文件 | `jsx/host.jsx` | `jsx/studio.jsx`（约 370 行，其中约 340 行原样搬自 host.jsx 1914–2200） |
| 后台全局名 | **`WINDWINGS_MH`**（原来是 `MH`） | **`WINDWINGS_STUDIO`** |
| 实况照片 | — | 留在 Studio 包内，和现在一样在 Studio 的导出里 |

**为什么沿用扩展 ID**：停靠位置（F11）、Studio 设置（F2）、面板上的「打开 Studio」按钮，都是按扩展 ID 找的，沿用就不用迁移。

**代价**：扩展 ID 不以包 ID 开头时能不能加载【未核实】。M0 真机摸底第一项就测；不行就换成「包 ID = 扩展 ID」的写法；还不行才换新扩展 ID（+1.5 人日：先发过渡版把设置写盘，用户要重新停靠一次 Studio）。

### 3.3 两边共用的品牌样式

- **不用 `../` 引用另一个包**。两个包可能装在不同的根目录，各自签名；跨包相对路径不受支持【可能】。
- **同步方式**：
  - 共用的 8 个文件（brand.css、bridge.js、icons.js、4 个字体、OFL.txt）只在面板包里改；
  - `node tests/shared.js --write` 同步到 Studio 包；
  - run-all 逐字节比对 SHA-256，不一致就失败。
- **style.css 拆成两份**：两边共用的 `brand.css`，加上面板专用的 `panel.css`。
  - 这样 3.9 加的面板样式（收藏星标、⋯ 菜单）不会牵动 Studio 文件夹。
  - 拆之前和拆之后要逐元素比较计算样式，范围包括悬停、按下、编辑模式、各个对话框、气泡、横幅、⌘K。**必须 0 差异才合并**；修不平就这一版整份共用 style.css。
- **brandlint.js**：机器检查品牌规则，包括
  - 字重不超过 500；
  - 不用阴影；
  - 线条只用 1px；
  - 颜色字面量只能出现在 brand.css 的 `:root` 里；
  - 字体只用 `var(--sans)` / `var(--mono)`；
  - 不能有外链。

  现有的 3 处阴影和 4 处 2px 线写进例外清单并注明原因，以后新出现的违规会让测试失败。

### 3.4 后台命名空间

- **两个全局各叫各的**：`WINDWINGS_MH` 和 `WINDWINGS_STUDIO`。名字长、不容易和别家扩展或用户脚本撞（F1）。
- **bridge.js 不再写死全局名、后台文件和版本**，改为从页面 `<html data-mh-ns data-mh-host data-mh-version …>` 读取，两个包共用同一份 bridge.js。
- **按身份判断后台是否还在**：后台返回的对象带 `bundle` 和 `version`。bridge.js 判断「是不是我们自己的那个对象」，而不只是 `typeof === "object"`：
  - 被别人覆盖了 → 用 `$.evalFile` 重新载入自己的后台；
  - 版本不一致 → 不自动重载，由自检报告。
- **新旧共存的过渡期**：3.8 的 host.jsx 收到 Studio 的 7 个旧调用名时（AE 没重启、旧 Studio 还开着），返回「重启 After Effects：Studio 已更新为单独的扩展，重启后从「窗口 → 扩展 → MotionHub Studio · 剪辑排版」打开」。
- **插件目录不再只靠 `$.fileName`**。Cookbook 提醒第一个加载的 JSX 里不要用它。改为前端把插件目录传给后台，后台收不到时才退回用 `$.fileName`。

### 3.5 面板 → Studio

**点「打开 Studio」时**：总是调用 `requestOpenExtension`（ID 不存在时静默失败，没有副作用【可能】），再按检查结果给出气泡。

| 状态 | 怎么判断 | 气泡 |
|---|---|---|
| 已装好 | `getExtensions` 列表里有它 | 已打开 Studio：在单独的窗口里；没看到就从「窗口 → 扩展 → MotionHub Studio · 剪辑排版」切过去 |
| 刚装上，AE 没重启 | 列表里没有，但磁盘上有 Studio 包。磁盘检查覆盖 Mac 的 2 个目录和 Windows 的 3 个目录 | 重启 AE 再打开 Studio：AE 开着时装的扩展要重启后才能用。重启后还是这样，就会改说「重新安装 Studio」 |
| 没装 | 两处都没有 | 安装 MotionHub Studio：3.8 起 Studio 单独安装，运行安装包里的「安装-Mac.command」（Windows 用「安装-Windows.bat」），再重启 AE |

- 按钮外观不变，也不变暗。`getExtensions` 列的是「已安装」还是「已打开」的扩展【未核实】，判断错了会把装好的 Studio 显示成没装。
- **面板自检加一行「Studio」**，显示已安装的版本，或者怎么装。
- **以后**：如果要「把当前合成直接送进 Studio」，用邮箱文件加打开扩展来实现，不只靠 CSEvent。事件不排队，冷启动的 Studio 收不到它启动之前发出的事件【可能】。这不在 3.8 里做。

### 3.6 Studio 设置写盘，以及 Studio 单独使用时的写入权限

**设置写盘**
- **存哪里**：7 项设置从 localStorage 挪到 `userData/MotionHub/studio.json`。用 Studio 已有的 Node `fs` 写，不经过 ExtendScript，不需要 AE 的写入开关。
- **读的顺序**：studio.json → localStorage → 默认值。
- **第一次启动**：把还在的旧设置写进 studio.json。
- **怎么写**：
  - localStorage 立刻写；
  - studio.json 在停手 400 ms 后写，先写 `.tmp` 再改名；
  - 关窗口前补写一次。
- **回滚过又升级时不吞改动**：每次写盘，在本机缓存里记下这次内容的哈希。下次启动如果发现本机缓存被旧版 Studio 改过，就以本机缓存为准，被替换掉的那份留在 studio.json 的 `replaced` 字段里。
- **坏文件、写不进去**：不覆盖原文件，在底部提示栏说一次原因和修法。

**写入权限**
- 只装 Studio 时，没有面板的横幅替它提醒写入权限。
- 「导入 AE 合成」的临时文件夹改由 Node 在系统临时目录里建好再传给后台，这样导入不再依赖这个开关。
- 仍需要 ExtendScript 写文件的操作，先检查开关，没开时说明怎么开。

### 3.7 版本与发版节奏

- **这次**：两个包都是 **3.8.0**。Studio 不从 1.0 重新开始，免得左上角的版本号看起来倒退。
- **以后各发各的**：
  - MotionHub 跟着功能走；
  - Studio 有改动才发。3.6、3.7 里 Studio 只改了 9 处版本号，说明它本来就不必跟着发。
- **版本号**：`node tests/bump.js studio 3.8.1` 一次改完一个包里所有写版本号的地方（manifest 6 处、`?v=`、页面版本标签、后台 VERSION），然后自动跑一致性检查。
- **标签和发版闸**：
  - 打 `motionhub-vX.Y.Z` / `studio-vX.Y.Z` 标签；
  - 发版前跑 `versioncheck --release`：包文件夹自上个标签以来有改动、版本号却没变大，就失败；
  - 同时检查许可证随包：有字体就要有 OFL.txt；有 livephoto.js 就要有 Apache NOTICE。
- **安装包**：
  - 合装包，文件名带两个版本号，例如 `MotionHub_v3.9.0_Studio_v3.8.1.zip`。任何一个包发版都重新打一次；
  - Studio 单装包，Studio 单独发版时发；
  - 不发「只有面板」的包，免得新用户漏装 Studio。
- **兼容范围**：两个包之间没有运行时接口，3.8 及以后的任意组合都能用。3.7 及以前的面板包不能和独立 Studio 同时装，安装脚本会拦住。

### 3.8 安装、升级、回滚

**安装脚本，Mac 和 Windows 同一套逻辑**
1. **预检，不改任何文件。**
   - 检查已装版本（用户目录和系统目录里取版本高的那份）。
   - 发现两个包会声明同一个扩展 ID 的组合，就拒绝，并说明怎么办。
   - 如果安装包比已装的旧，跳过这个包，并提示「要退回旧版，运行回滚脚本」。降级只有回滚脚本这一个入口。
2. **等 AE 完全退出。** 用 `pgrep -x`；可以按 Q 放弃，什么都不会改。
3. **两阶段安装。**
   - 先把新包复制到暂存目录（和扩展目录在同一个卷上），逐个校验：manifest 版本等于安装包版本，文件数一致。
   - 全部通过后，才把旧包移进备份、把新包移进扩展目录。
   - 任何一步失败，就按已完成的步骤反向恢复，提示「重新运行安装脚本：…已恢复成安装前的样子」。
   - 只有校验通过才打印 ✓。
4. **备份**
   - 位置：Mac 是 `~/Library/Application Support/windwings/backup/<时间>/`，Windows 是 `%APPDATA%\windwings\backup\`。
   - 保留最近 3 次；另外，每个包最近一份「和当前版本不同」的备份永不自动删除，保证总能退回上一个大版本。
   - 系统目录里的旧版用 `sudo mv` 移进备份，不再直接删掉，回滚时放回原处。
5. **缓存**：只删 HTTP 缓存，保留 Local Storage（同 H2）。

**Windows 改用 PowerShell 写逻辑**
- `.bat` 只留几行启动器，逻辑放进同目录的 `install.ps1`，存成带 BOM 的 UTF-8。
- 原因有两个：
  - 原型的 `.bat` 在括号块里展开 `%ProgramFiles(x86)%` 会出错（静态发现）；
  - 中文用户名路径在 cmd 里容易出问题。
- `install.ps1` 能在 Linux 上用 pwsh 跑同一套测试场景，Windows 逻辑因此可以进 run-all。

**回滚脚本**
- 读备份里的 `installed.txt`（第一行写格式版本），一步退回上一次安装。
- 如果恢复出来的是自带 Studio 的旧面板包，就把独立 Studio 移进备份，保证只有一个包声明那个扩展 ID。

**其他**
- README 和两个 `.command` 的说明同时写 macOS 14 及以前、macOS 15 及以后打开未签名脚本的做法。macOS 15 去掉了「右键 → 打开」这条路【可能】。
- 卸载：删掉扩展目录里的两个包文件夹即可。布局、设置和脚本库都在扩展目录外面。

## 4. 需求 A：脚本平台，版本 3.9.0（约 15 人日）

### 4.1 A1：面板类脚本以浮动窗口打开，要说清楚

**识别**
- `.jsx` 不超过 256 KB 读全文；更大的读开头和结尾各 64 KB，用绝对位置 `seek`。
- 匹配 `instanceof Panel` → 标记 `panel: true`；匹配 `/["']palette\b/i` → `palette: true`（有浮动分支）。
- `.jsxbin` 看不出来，标 `panel: null`。
- 识别结果缓存在 `$.global` 里，按「路径 + 修改时间 + 大小」做键，4 个面板重新载入后台也不会再读一遍。
- 每次扫描设读取总量上限，脚本很多的库也不会让 AE 卡住。

**4 个运行入口合成一个 `runScript`**：面板按钮、▶、双击、⌘K。统一处理说明文案、最近使用和报错显示。

**面板脚本在每个入口都说清楚**
- 提示栏：「单击 — 打开浮动窗口」。
- 补一句：「从 MotionHub 运行的面板脚本会以浮动窗口打开（AE 的限制）。要停靠进工作区：点 ⋯ →「安装为可停靠面板」」。
- 运行结果：「已打开「X」的浮动窗口」。

### 4.2 A2：一键安装为可停靠面板

**入口和目标文件夹**
- **只有一个入口**：脚本行的 ⋯ 菜单 →「安装为可停靠面板」。添加对话框里那个对拖放不生效、还会把非面板脚本也装进去的勾选框删掉。
- **目标文件夹**：`<首选项>/<主.次>/Scripts/ScriptUI Panels`（F4）。
  - 版本文件夹不存在时不替 AE 建，避免装到 AE 根本不读的地方；
  - 改为引导用户用 AE 自带的「文件 → 脚本 → 安装 ScriptUI 面板…」（F6）。

**不确定能不能停靠时，先问再装**
- 看不出是面板的脚本（普通 `.jsx`、`.jsxbin`），菜单项照样能点，点了先问：
  - 「看不出「X」是面板脚本。装进去后如果「窗口」菜单里多出一个空面板，在 ⋯ 里点「卸载停靠面板」就行」；
  - 按钮：取消 / 仍要安装。
- 这和「变暗的按钮仍然可以点」是同一条规则。

**同名冲突和备份**
- 遇到不是 MotionHub 装的同名文件，先问；替换前先备份。
- 安装清单：每次变动都用「`.tmp` → `.bak` → 正式文件」的顺序写，另外追加一行日志，文件丢了也能重建。

**依赖文件**
- 脚本用 `#include` 或相对路径的 `$.evalFile` 引用了别的文件时，在确认框里列出来，提供「一起复制」。
- 不然要等重启 AE 之后才发现打不开。

**装好以后**
- 对话框说明「重启 AE → 窗口菜单最下面」，并直接带「撤销安装」按钮。
- 文件系统的改动进不了 AE 的撤销历史，所以「撤销安装 / 卸载」是明确的反向操作：
  - 移进备份，而不是直接删除；
  - 原来被替换的同名文件放回去。
- 「现在重启 AE」按钮先不做：`app.restart()` 从 AE 25.4 才有，遇到未保存的工程会不会提示保存【未核实】。

**重启后，以及 AE 升级后**
- 重启后检查有没有出现在菜单里：按「本次 AE 启动」的时间戳判断有没有重启过，再用 `findMenuCommandId(文件名)` 查菜单（中英文界面都要真机确认）。
- AE 升级小版本后，旧版本里装的停靠面板不会自动带过来（F4），顶部横幅提示「重新安装 2 个停靠面板：AE 升级到了 24.4，旧版本里装的不会自动带过来」。

### 4.3 A3：最近使用和收藏

**存在哪里**
- **最近使用**：本机 `userData/MotionHub/recent.json`，最多 20 条。
  - 换了脚本库就从空开始；
  - 文件找不到了就不显示。
- **收藏**：`<脚本库>/_favorites.json`，跟着脚本库走，换电脑或网盘同步时都在，做法和 `_snippets.json` 一样（**决定项 4**）。
  - 永不自动删除；
  - 文件被挪了，而库里正好只有一个同名文件，就跟过去；
  - 面板上同一个脚本的按钮用同一条规则解析。

**写入**
- 读-改-写在后台一次调用里完成；收藏用「设成」而不是「切换」，所以双击或两个面板同时点都不会改反。
- 所有状态文件都按「`.tmp` → `.bak` → 正式文件」写，读不出来就读 `.bak`；坏文件另存 `.bad`，原内容不丢。

**界面**
- 分类下拉加「★ 收藏」「最近使用」两项（180px 宽也放得下）。
- 行内悬停按钮改为 [☆ 收藏] [放到当前面板] [⋯] [▶]。「在文件夹中显示」和「移除」收进 ⋯。
- ⌘K 空查询时，先列最近，再列收藏；有查询时，同一匹配程度下收藏的排在前面。现在 ⌘K 截到 40 条，工具排在前面，21 个脚本只露出 1 个，这一版一起修掉。

**范围**：v1 只做脚本文件，代码片段不参与（**决定项 5**）。

### 4.4 A4：显示脚本自己的原始报错

**后台**
- 在 `$.evalFile` 外面捕获错误，取 `message`、`line`、`fileName`。
- 返回时标记 `origin:"script"`，和 MotionHub 自己的内部错误分开，不再统一写「出错了」。
- `throw null` / `throw undefined` 时，`call()` 不再自己崩掉。现在会崩，前端还会误报「后台本身正常」，原型的对照测试复现过。

**前端**
- 气泡：短句，例如「运行「X」出错：脚本报错「foo is undefined」（第 12 行）」。
- 提示栏：原文、修法，加一个「查看报错」按钮。
- 对话框：「「X」运行时报错，下面是脚本自己的原话」，文本框可以选中，带「复制报错」。
- 复制出去的内容不带绝对路径，免得把用户名带出去。

**拿不到的报错，如实说明**
- 浮动窗口里按钮回调出的错：那时 evalFile 早已返回，由 AE 自己弹窗提示；
- 脚本自己用 `alert` 弹出的提示；
- AE 的原生警告。

### 4.5 撤销和全局名保护

- **撤销组**：只给「`.jsx`、不是面板、也没有 palette 分支」的脚本外面套一层撤销组「运行「X」」。这类脚本的修改都在 evalFile 期间同步完成，套了就能一步撤销（F8）。
- **不套的情况**：
  - `.jsxbin` 和面板脚本，套了会留下空的撤销记录；
  - 脚本在自己的撤销组里出错，或多关了一次撤销组时，外层组会不会触发 AE 的警告【未核实】，所以真机确认（R2、R16）之前这一项保持现状。
- **全局名保护**：脚本跑完后检查 `WINDWINGS_MH` 是不是自己的，不是就恢复并提示。3.8 改名之后，这种情况几乎不会再发生。

### 4.6 A 的测试

## 6. 主要风险

1. **真机依赖多。**
   - 扩展 ID 跨包加载、停靠位置、缓存目录布局、`getExtensions` 语义、evalFile 报错字段、空撤销组，都要真机确认。
   - 每一项都设计了「确认前保持现状」的默认值和备选，最坏情况是多一次重新停靠，或设置回到默认值，不会丢布局、片段和脚本库。
2. **同一个扩展 ID 出现在两个包里**【未核实】。正常路径由安装预检、发版检查和回滚脚本挡住。但手动拷文件夹，或用 3.7 的老安装脚本回退时仍可能发生，README 要写明手动回退的步骤。
3. **共用文件有两份，发版纪律是新的。** 靠 shared.js、versioncheck 和标签来保证。代价是改共用文件时多一条命令，而且 Studio 要等它下次发版才拿到修复。
4. **CEP 被淘汰的时间表**【未核实】（F14）。这次的投入以「搬家」为主，前端代码和 brand.css 以后能带到 UXP，ES3 后台带不过去。
5. **工作量。** 26 人日已经按批评意见上调过（原来是 20）。Windows 安装脚本和 CSS 拆分是最容易超支的两块。

### 其余按推荐默认（有异议再说）
- 拆分用「最小改动 + 嫁接」，不建 monorepo，不加构建步骤。
- brand.css / panel.css 拆分以计算样式 0 差异为前提，修不平这一版就整份共用。
- 安装时只删 HTTP 缓存，保留 Local Storage；安装前自动备份；带回滚脚本；不能降级。
- Windows 安装逻辑改用 PowerShell。
- 安装包：合装包（文件名带两个版本号）+ Studio 单装包，不发「只有面板」的包。
- 「打开 Studio」不做握手确认，没装时不变暗。
- 停靠面板安装入口只在 ⋯ 菜单里，删掉添加对话框的勾选框。
